# GNU gettext spec — audit checklist

Authorities: the GNU gettext manual, PO file format, MO file format and the `Plural-Forms` header
(<https://www.gnu.org/software/gettext/manual/html_node/PO-Files.html>,
<https://www.gnu.org/software/gettext/manual/html_node/MO-Files.html>,
<https://www.gnu.org/software/gettext/manual/html_node/Plural-forms.html>).
The package's own README maps its classes to these; this file is the verification checklist.

## PO format

- **Entry parts**: translator comments `#`, extracted comments `#.`, references `#:`, flags `#,`
  (`fuzzy`, `c-format`, `php-format`, `no-wrap`, ...), previous translation `#| msgid`, then `msgid`,
  `msgctxt`, `msgid_plural`, `msgstr` or `msgstr[n]`.
- **Header entry** (`msgid ""`): `Project-Id-Version`, `Report-Msgid-Bugs-To`, `POT-Creation-Date`,
  `PO-Revision-Date`, `Last-Translator`, `Language-Team`, `Language`, `MIME-Version`, `Content-Type`
  (charset), `Content-Transfer-Encoding`, `Plural-Forms`, `X-Generator`.
- **Escapes**: `\n \t \r \" \\ \a \b \f \v`, `\uXXXX`, `\UXXXXXXXX`, `\xHH`, octal. The strict loader
  advertises the C/C++ extensions (`\u`, `\U`, `\x`, octal).
- **Obsolete entries** use the `#~ ` prefix.
- **Wrapping**: generators must not wrap a message flagged `no-wrap`; multi-line strings are split over
  consecutive quoted lines.
- **Contexts** prefix translations with `msgctxt` and, in MO, `context\x04msgid`.

## MO format

- 7-word header, all 32-bit: magic `0x950412de` (little-endian) or `0xde120495` (big-endian), file format
  revision, number of strings N, offset of the original-strings table, offset of the translation-strings
  table, hash-table size, hash-table offset.
- Each table holds N `(length, offset)` pairs; offsets are from the start of the file; strings are
  NUL-terminated.
- Entries are **sorted by msgid** (byte order).
- msgid form: `msgid` or `context\x04msgid`, plus `\x00plural` when a plural exists.
- msgstr form: `singular\x00plural0\x00plural1...` (the first plural form is the singular msgstr).
- The hash table is optional; size 0 is valid.

## Runtime plural selection

- `Plural-Forms: nplurals=N; plural=EXPRESSION;` where EXPRESSION is C boolean over integer `n`
  (gettext evaluates it with **integer arithmetic**; `n` is the absolute value).
- The expression returns the plural index in `[0, nplurals-1]`.

## Candidate gaps to verify in this package (investigation leads, not confirmed)

- `Generator/MoGenerator.php` writes every word with `pack('L', ...)` — PHP `L` is the machine's unsigned
  long byte order, so a big-endian host would emit the swapped magic. GNU MO canonical output is
  little-endian (`pack('V', ...)`). Reproduce by generating a `.mo` and checking the first 4 bytes, then
  decide whether to force little-endian (or emit an explicit byte order and document it).
- `Generator/MoGenerator.php` builds the header msgstr by joining headers with `"\n"` and **no trailing
  newline**; a GNU header msgstr conventionally ends with a blank line. Compare generated bytes against a
  known-good reference header.
- `Generator/MoGenerator.php` skips entries whose `translation` is falsy (`if (!$translation->translation ...)`),
  which drops a legitimate translation of `"0"`.
- `Loader/MoLoader.php` uses `array_filter($v)` on the plural translations, which drops the falsy (but valid)
  string `"0"` **and** empty strings; filter strictly with `!== ''`.
- `Loader/MoLoader.php` `readInt()` returns `0` on malformed input, masking a corrupt file; decide whether
  malformed offsets/indices should throw.
- Round-trip parity: `PoLoader`↔`PoGenerator`, `StrictPoLoader`↔`PoGenerator`, `MoLoader`↔`MoGenerator`,
  `ArrayLoader`↔`ArrayGenerator`, `JsonLoader`↔`JsonGenerator`. `StrictPoLoader` is the GNU-aligned parser
  and must keep throwing/warning precisely (line/byte, plural-count mismatch, missing header, dangling
  comments) with its `displayErrorLine`/`throwOnWarning`/`getWarnings()` options.
- Loaders reject invalid input: `ArrayLoader` non-array, `JsonLoader` non-object JSON.
- Scanner: `PhpScanner`/`JsScanner` recognition set (`__`, `n__`, `p__`, `d__`, ...; `setDefaultDomain`,
  `extractCommentsStartingWith`) must match the README and the runtime helpers, and reject non-string
  required gettext arguments.
